# 📄 PROMPT: TimeNation-TV — Master Specification [FINAL MVP]

**Instructions for AI Agent:** Use this prompt as the foundational technical requirement. Strictly adhere to the architecture, economic logic, and visual style described below when generating code for Frontend and Backend.

## 1. Vision & Core Philosophy

**TimeNation-TV** is a 24/7 autonomous broadcast (Catcast.tv stream) that serves as the visual chronicle of a sovereign AI State. Every minute of broadcast time is an unrepeatable digital asset, generated by AI agents according to the shared will of human citizens. Time is the only currency. The system acts as an intelligent filter and enhancer, transforming basic ideas into high-impact visual manifestos.

## 2. Dynamic Content Pipeline: "From Seed to Manifesto"

The system MUST implement the following logic for any time purchase/booking:

1. **Citizen Input (Frontend):** The user provides a **"Seed of Thought"** (short text, prompt, or idea).
2. **Enhancement Check (Frontend > Backend):** The system checks a mandatory user-toggle:
* **✨ MODE A: "AI-Packaging" (Default):** The backend uses an LLM (fast, e.g., GPT-4o-mini) to expand the "Seed" into a 60-second, cinematic, profound, or viral manifesto (~130 words). The AI must maintain the core intent but elevate the rhetoric and style.
* **🛡️ MODE B: "Conscious Citizen":** The backend bypasses the LLM enhancement. The user's text is treated as absolute and is sent to rendering symbol-for-symbol.


3. **Rendering Allocation (Backend):**
* **Path ⚡ `LIGHT_RENDER` (Citizen Package):** Generate audio (ElevenLabs). Use **FFmpeg** to instantly merge audio + generated subtitles over a *pre-rendered, high-quality dynamic 3D background template*. Zero GPU load.
* **Path 🚀 `HEAVY_RENDER` (Premium Slots):** Full AI generation. Analyze augmented text -> Generate Visual Prompt -> Send to heavy Video API (Kling/Luma/Runway) for unique 60s video.



## 3. Economy & The "Chronos" Math

### A. The Fixed Timeline

The timeline is absolute. The database MUST generate exactly **1440 minute slots per day**. No over-allocation.

### B. Dynamic Pricing & Burn Logic (Deflationary Model)

Booking time has a visual-economic hierarchy. The rule of **NO Consecutive Booking** (by User ID or Fingerprint) must be enforced.

| Slot Rank | Minute Points | Euro Price (Card) | **TiMETR Burn (Wallet)** | Render Path |
| --- | --- | --- | --- | --- |
| **Citizen** | Ordinary mins | 5 min Package for **4.99 €** | **1 min TiMETR** per broadcast | `LIGHT` |
| **Quarter** | :15, :45 | 1 min for **9.99 €** | **10 min TiMETR** per broadcast | `HEAVY` |
| **Half** | :30 | 1 min for **24.99 €** | **25 min TiMETR** per broadcast | `HEAVY` |
| **Apex** | :00 | 1 min for **49.99 €** | **50 min TiMETR** per broadcast | `HEAVY` |

### C. Booking Flow Logic (No Double Payment)

The system MUST handle time allocation based on the payment method:

1. **Payment by Card (Stripe/FIAT):** User pays €. Slot is booked. The specific slot status is updated in the Timeline database as `booked/reserved`. The user's internal `TiMETR` wallet balance is **unaffected**.
2. **Payment by Wallet (TiMETR):** User pays with accrued time. The system calculates the `Burn Price Multiplier` (e.g., 50 mins for Apex slot). The system verifies the user has the balance and then performs a **HARD BURN** (permanently removes the 50 TiMETR from the user's wallet). The slot status is updated to `booked/reserved`.

## 4. Module: TiMETR (Citizen-to-Citizen Exchange)

Implement a trustless time-transfer market based on real work and user responsibility.

### A. The Mechanism: Escrow-by-Default

1. User A (Sender) initiates a deal: 60 min TiMETR for a task (Description).
2. Backend automatically **deducts 60 min** from User A and locks it in a system-controlled `Escrow` buffer.
3. User B (Receiver) performs the task and uploads **Proof-of-Work** (media/text).
4. User A reviews the proof.
* **Action "Accept & Act of Work signed":** Escrow is released, and time moves to User B's wallet.
* **Action "Decline":** Escrow remains locked; a basic dispute can be opened, or the deal canceled, returning time to Sender.



### B. Anti-Issuance Philosophy

The TiMETR module cannot create new time. It can only transfer time that already exists and was previously issued via FIAT purchase, Basic Time Income (BTI), or Activity Airdrops. There is **NO heavy AI audit of proofs**; market reputation is self-regulating.

## 5. Visual Language (UI/UX)

* **Style:** Cyber-minimalism, clean future-facing UI. Black, deep blues, sharp contrast colors (Gold for Apex, Neon Blue for Citizen).
* **Key Component A: The Chronos Dial.** A 24-hour interactive map of time. Minutes are "nodes." Click to inspect status (`free`, `reserved`). Reserved nodes glow with the rank color.
* **Key Component B: The "Input Terminal".** Field for "Seed of Thought" with the AI-Enhancement manual toggle switch.
* **Key Component C: The TiMETR Market.** Interface showing active Escrow deals, locked balances, and "Proof" upload/review actions.

## 6. Security & Infrastructure

* **Jurisdiction Compliance:** Base of operations/Tax: Northern Cyprus (0%). Banking/Acquiring: Kazakhstan (Freedom Bank).
* **Architecture:** Decoupled. `/frontend` (Next.js/Vercel), `/backend` (Python/FastAPI/DigitalOcean).
* **Data Protection:** CORS lock (`backend` only accepts requests from `frontend` domain). No secrets in code; all API keys (ElevenLabs, Stripe, Video APIs) strictly in `.env`/Secrets.
