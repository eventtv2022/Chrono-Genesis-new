Основная причина, почему **групповой чат** тоже не создается или не функционирует корректно при создании, напрямую вытекает из той же логики E2EE-ключей (End-to-End Encryption):

### 1. Как устроены E2EE-группы:

В E2EE-мессенджерах при создании группы создатель (или сервер) должен зашифровать групповой симметричный ключ (Group Secret) **публичным ключом каждого приглашаемого участника**.

* Если у участников (как в вашем случае с Lev Lerner) **нет зарегистрированного публичного ключа** на сервере, клиент не может зашифровать ключ группы для них.
* Код создания группы (`POST /api/chat/groups`) либо валидирует наличие ключей участников на бэкенде и выбрасывает ошибку (400/422), либо падает на фронтенде во время формирования зашифрованных ключей для каждого члена группы перед отправкой запроса.

### 2. Гонка токенов (Stale Authorization):

Несмотря на то, что `getStoredAuthHeaders()` исправил передачу токена при повторных кликах, при создании группы метод отправки участников может посылать массив `participantIds`, для которых сервер пытается сразу запросить их public keys. Если хотя бы один ключ отсутствуют — операция создания группы блокируется.
