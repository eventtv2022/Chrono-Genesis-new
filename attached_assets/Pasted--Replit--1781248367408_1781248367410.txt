Суть бага и ваша новая задача ясны: сейчас Replit-агент просто рендерит видеофайлы и складывает их на страницу как изолированные плееры. Получается статичная лента, а не **живое непрерывное телевидение 24/7**, где в каждую конкретную минуту суток (от 0 до 1439) должен автоматически подгружаться и проигрываться соответствующий медиа-поток.

Чтобы пересобрать логику под формат сквозного эфира в одном окне (как на `catcast.tv`), фронтенд должен постоянно вычислять текущую системную минуту и бесшовно переключать треки внутри **одного главного плеера**.

Вот готовый, жесткий технический промт для Replit-агента, который полностью устранит этот разрыв и запустит вещание 24/7.

# REPLIT ACTUATOR: MODULE "CHRONOS_STREAM_24_7" (ONE-WINDOW CONTINUOUS BROADCAST)

## 1. OBJECTIVE

Полностью переписать архитектуру отображения эфира во вкладке `TimeNation-TV`. Вместо генерации списка отдельных видеоплееров для каждой капсулы, реализовать **один главный интерактивный плеер**, который крутит эфир непрерывно 24/7. Логика воспроизведения должна строго привязываться к текущей системной минуте суток (`UTC_MINUTE_INDEX` от 0 до 1439).

## 2. REVISION OF THE PLAYBACK LOGIC (Continuous Broadcast Engine)

1. **Единое Окно Вещания:** На странице присутствует только один экземпляр HTML5 видеоплеера (или JS-плеера типа `HLS.js` / `video.js`).
2. **Динамическая синхронизация по времени (Time-to-Track Mapping):**
* При загрузке страницы скрипт определяет текущее системное время UTC и переводит его в индекс текущей минуты:

$$\text{current\_minute} = (\text{utc\_hours} \times 60) + \text{utc\_minutes}$$


* Плеер делает `GET` запрос к бэкенду `/api/v1/tv/live-slot?minute=current_minute` для получения ссылки на `.mp4` или `.m3u8` файл, забронированный на эту минуту.


3. **Бесшовный переход (Seamless Handshake):**
* Когда текущая минута подходит к концу, фронтенд в фоновом режиме (за 3–5 секунд до конца минуты) запрашивает URL видео для *следующей* минуты (`current_minute + 1`).
* Как только наступает новая минута, плеер мгновенно подменяет `src` и продолжает играть поток без перезагрузки страницы или остановки стрима. Если на минуту нет выкупленной капсулы, плеер играет дефолтный зацикленный медиа-файл (заставка-генератор TimeNation «Эфир ожидает Гражданина»).



## 3. FIXING BACKEND DATA ARCHITECTURE (FastAPI Update)

Убедись, что забронированные слоты падают в единую таблицу расписания, индексируемую по минутам:

```python
@app.get("/api/v1/tv/live-slot")
async def get_live_slot(minute: int, db=Depends(get_db)):
    # Валидация индекса минуты (0 - 1439)
    if not (0 <= minute <= 1439):
        minute = minute % 1440
        
    slot = db.query(BroadcastSlot).filter(BroadcastSlot.minute_index == minute, BroadcastSlot.status == "published").first()
    
    if slot:
        return {"minute_index": minute, "video_url": slot.video_path, "has_content": True}
    else:
        # Если слот пустой, отдаем системную заглушку (Default Screensaver)
        return {"minute_index": minute, "video_url": "/static/videos/timenation_idle_loop.mp4", "has_content": False}

```

* **Индикация «В ЭФИРЕ»:** Над главным плеером выводить плашку: `[Текущая UTC Минута Слота] | Гражданин: Gennadii Lerner | В ЭФИРЕ`.
* **Интерактивный таймлайн:** При клике на любую прошедшую или будущую ячейку в `Chronos Grid`, плеер не должен ломать живой эфир. Вместо этого сбоку или в модальном окне должна появляться возможность «Посмотреть архив капсулы» или «Забронировать эту минуту». Основной плеер всегда держит фокус на `LIVE-UTC`.
