Для интеграции полноценной аутентификации в Replit нам понадобятся:

1. **Хэширование:** Использование библиотеки `bcrypt` (или встроенного в Node.js `crypto`) для безопасного хранения паролей в базе.
2. **Токены восстановления:** Добавление в таблицу пользователей полей `resetPasswordToken` и `resetPasswordExpires`.
3. **Эндпоинты:** Маршруты `/api/auth/register`, `/api/auth/login`, `/api/auth/forgot-password` и `/api/auth/reset-password`.

## 1. OBJECTIVE

Модернизировать систему аутентификации пользователей (граждан). Добавить обязательное поле пароля (с хэшированием), эндпоинт авторизации (Login) и полноценный механизм генерации токенов для восстановления доступа при потере пароля.

## 2. DATABASE SCHEMA CHANGES

В схему таблицы пользователей/граждан (например, `citizensTable` или аналогичную таблицу авторизации в `db/schema.ts`) необходимо добавить три поля:

* `passwordHash` (text, not null) — для хранения хэшированного пароля.
* `resetPasswordToken` (text, nullable) — случайный безопасный токен восстановления.
* `resetPasswordExpires` (timestamp, nullable) — время жизни токена (например, 1 час).

If the user exists, generate a secure, random crypto token (e.g., using Node's native `crypto.randomBytes(32).toString('hex')`). Save this token as `resetPasswordToken` and set `resetPasswordExpires` to 1 hour in the future. For now, log the recovery link to the server console (`/api/auth/reset-password?token=XYZ`) so we can use it, or simulate sending an email.
> * **Reset Password (`POST /api/auth/reset-password`):** This route accepts `token` and `newPassword`. It must look up the user by `resetPasswordToken`, check if `resetPasswordExpires` is still valid (in the future), hash the `newPassword`, update `passwordHash`, and clear the token fields.
